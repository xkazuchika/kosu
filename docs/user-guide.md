# kosu 操作ガイド

kosu の画面ごとの操作手順を説明します。用語は次の通りです。

- **実績工数**: 実際に作業した時間（案件・タスク別）
- **総稼働時間**: 1日に作業した合計時間
- **予定工数**: 予定上の作業時間（月次・日別）
- **工数予算**: 案件全体で利用できる時間の目安
- **稼働可能時間**: その月に働ける予定時間（キャパシティ）

月次の業務の流れと締めの条件は [business-flow.md](./business-flow.md) を参照してください。

## 初期セットアップ

初回起動時、ワークスペースが未作成の場合は `/setup` にリダイレクトされます。

1. ワークスペース名、タイムゾーン、管理者氏名、メールアドレス、パスワードを入力します。
2. 「セットアップを完了する」を押します。
3. 完了後、ログイン画面に遷移します。

セットアップは1回だけ実行できます。以降は `/login` からログインしてください。

## ログイン・ログアウト

- **ログイン**: `/login` でメールアドレスとパスワードを入力します。
- **ログアウト**: 画面右上の「ログアウト」ボタンを押します。

権限は2種類です:

- **管理者**: メンバー管理、案件管理、月次予定工数入力、インポート、期間ロック、設定が可能
- **メンバー**: 自身の実績・予定入力、自己アサイン、レポート閲覧が可能

## ダッシュボード

`/dashboard` はログイン直後の画面です。役割に応じて今日やるべきこと、月次の状況、案件状況を表示します。

- **今日の作業**: 今日の実績入力状況と入力へのリンク
- **Workflow**: セットアップ → 予定 → 実績 → レビューの流れ
- **今月の状態**: 予定工数、実績工数、未割当・超過、月次工数提出、ロック状態

管理者には当月の「提出済み / 対象」人数と、下書きのメンバーへのリンクも表示されます。

ダッシュボードのリンクはコンテキストに応じた次の作業へ誘導します。

メンバーの **未割当・超過** は、当月の差分がある実績工数だけに絞った一覧を開きます。該当する日付から、直接その日の入力画面へ進めます。

## 実績工数入力

### 日別工数実績入力

`/work-logs` から日付を選び、`/work-logs/:date` で日別の実績を入力します。総稼働時間と案件別実績工数は 1 つのフォームになっており、**1 回の保存でまとめて反映**されます。

1. 対象日を選択します（前日・今日・翌日のボタンで移動可能）。
2. **総稼働時間** を入力します（0.25h単位、24h以下）。
3. **案件別実績工数** の表で、案件・タスク・実績時間・備考を入力します。複数案件に分けるときは「行を追加」を押します。
4. 未割当がある行で「残りを全部」を押すと、その時点の残時間を入力できます。
5. 「実績をまとめて保存」を押します。画面上から消した既存行は、この保存時に削除されます。

なお、総稼働時間と案件別実績工数は別々に入力します。総稼働時間は「その日に働いた時間」、案件別実績はその内訳です。差がある場合は未割当・超過として表示され、月次締めの完全性チェック対象になります。

日付は実在するカレンダー日だけを受け付けます。案件別実績は各行と1日の合計がそれぞれ24h以下である必要がありますが、総稼働時間との不一致は修正途中の状態として保存でき、未割当・超過で通知されます。一度0hでクリアした日も再入力でき、過去に削除した案件別実績が自動復元されることはありません。

- 案件は**最近使った順**に並びます。
- 行の「行を削除」で下書きから外せます。最後の1行は入力欄として残ります。
- 総稼働時間と実績の合計に差がある場合、**「未割当 Nh」**、**「割当完了」**、**「超過 Nh」** が入力中に変わります。総稼働時間は8時間固定ではなく、5時間や9.5時間など実際に働いた時間を入力します。
- 「今日の予定から下書き」はその日の日別予定を、「直近勤務日から下書き」は最も近い利用可能な過去実績をフォームへ読み込みます。どちらも下書きの時点では保存されません。内容を確認して「実績をまとめて保存」を押してください。
- 対象日に既に実績配賦がある場合、下書き作成で上書きしません。アーカイブ済み案件や現在アサインされていない案件は過去候補から除外されます。
- 入力内容に 1 行でも不備があると、何も保存されずにエラーが表示されます。

### 週次工数実績入力

`/work-logs/week` では、月曜から日曜までの総稼働時間と案件別実績をまとめて編集できます。

1. 「前週」「翌週」で対象週を移動します。日別入力へ戻るときは「日別入力」を押します。
2. 上段に各日の実際の総稼働時間を入力します。
3. 案件・タスク・備考を行ごとに選び、各日の実績時間を入力します。同じ案件行を1週間で再利用できます。
4. 各列の「配賦 / 差分」で、完了・残り・超過を確認します。
5. 「週の実績を保存」を押します。1日でも不正な入力がある場合は週全体を保存せず、下書きを画面に残します。

週が月をまたぐ場合は両方の月の締め状態を確認します。工数レビュー中・確定済み、または原価レビュー中・承認済みの月を含む週は読み取り専用です。

### 未割当・超過の修正

`/work-logs` では、対象月と状態を指定して日別実績を確認できます。

1. **対象月** を選択します。初期表示は当月です。
2. 状態で **未割当・超過のみ** を選択し、「表示」を押します。
3. 差分がある日付を選択して、総稼働時間または案件別実績工数を修正します。

ダッシュボードの **未割当・超過** カードまたは警告リンクから開く場合は、当月かつ **未割当・超過のみ** があらかじめ選択されています。保存済みの日別実績だけが対象で、実績自体が未入力の日は一覧に含まれません。管理者は対象メンバーを選んで同じ絞り込みを使用できます。

### 月別総稼働時間入力

`/work-logs/month` では、日別の総稼働時間をまとめて入力し、その月の工数を提出できます。

1. 各日の勤務時間と案件別実績工数の差分を0にします。不一致の日付は提出欄から直接修正画面を開けます。
2. 「この月の工数を提出」を押します。実績が0時間でも、提出対象者は明示的に提出してください。
3. 提出後に実績を作成・更新・削除・クリア・コピーすると、対象のメンバーと月だけが下書きへ戻るため、修正後に再提出します。

メンバーは自分自身を提出できます。管理者は対象メンバーを選び、無効化済みでも当月の予定・能力・実績・提出などの証跡があるメンバーを代理提出できます。画面には実際に操作した提出者と時刻が表示されます。工数レビュー中・確定済み、または原価レビュー中・承認済み月は提出できません。

`/work-logs/month` で1ヶ月分の総稼働時間を一括入力します。

1. 対象月と対象メンバー（管理者は切替可能）を選択します。
2. 各日付の「総稼働」欄に時間を入力します（0.25h単位、24h以下）。
3. 「保存」を押します。

行の曜日と土日が色分けされます。各日の「入力」リンクから日別詳細画面へ移動できます。

工数レビュー中・確定済み、または原価レビュー中・承認済みの月は、メンバーと管理者のどちらも閲覧のみです。修正する場合は、管理者が月次締めから理由を記録して再オープンします。

## 予定工数入力

### 日別予定工数入力

`/daily-plans` で、いつどの案件に何時間入る予定かを入力します。

1. 対象月と対象メンバー（管理者は切替可能）を選択します。
2. 表示案件にチェックを入れます（既定は月次予定のある案件）。
3. 日付行 × 案件列のセルに予定時間を入力します（0.25h単位）。
4. 「保存」を押します。

空欄または0は予定なしとして扱われます。各セルまたは1日の合計が24hを超える予定は保存できません。

### 月次予定工数

`/monthly-plans` で、自分の案件別の月次予定工数・実績工数・残りを確認します。管理者は `/monthly-plans/admin` で入力・編集でき、案件全期間の工数予算、割当済み予定、未割当枠も確認できます。

1. 対象月を選択します。
2. 案件ごとに予定工数、担当ロールを入力します（管理者）。
3. 「保存」を押します。

既存の行は更新・削除できます。予定工数の合計が案件工数予算を超えても保存でき、管理判断のため「予算超過」と表示されます。稼働可能時間（キャパシティ）は任意で入力します。

### 予定から実績への反映

`/daily-plans` で「実績工数へ反映」を実行すると、保存済みの日別予定工数から実績工数を作成します。

- 既に実績工数がある日はスキップされます。
- 未保存のセル編集は反映されません。先に保存してください。

## レポート

### 工数実績レポート

`/reports` で、案件・メンバー・月ごとの実績工数を確認します。

1. 対象月や絞り込み条件を選択します。
2. 表で実績工数を確認します。
3. 必要に応じて「CSV出力」を押します。

管理者とメンバーで出力内容が異なります（原価情報は管理者のみ）。

### 予定工数対実績工数

`/reports/planned-vs-actual` で、予定工数と実績工数を比較します。

1. 対象月を選択します。
2. メンバーごとに予定工数、実績工数、差分を確認します。
3. 必要に応じてCSV出力します。

予定工数がない場合は、月次予定工数の入力を促すガイドが表示されます。

## 案件

### 案件管理

`/projects` で案件一覧を確認します。管理者は案件の作成・編集・アーカイブができます。

1. 「新規作成」から案件コード、名称、種別、任意の工数予算、請求対象案件に必要な契約売上・人件費予算を入力します。
2. 案件詳細で工数予算に対する全期間の予定・実績・残りを確認し、タスク、アサイン、月次予定工数を管理します。
3. 不要になった案件はアーカイブします。

### タスク管理

案件詳細の「タスク」で、案件配下のタスクを作成・編集・アーカイブします。実績工数入力時にタスクを紐付けられます。

### アサイン管理

案件詳細の「アサイン」で、アクティブなメンバーをアクティブな案件にアサインします。1メンバー・1案件につき有効なアサインは1件で、担当ロール（例: Engineer）は既存アサイン上で編集できます。解除後の再アサインでは、解除済み行を履歴として残したまま新しい有効行を作成します。

### 自己アサイン

`/self-assign` で、メンバー自身が既存のアクティブな案件へアサインできます。

## 管理（管理者のみ）

### メンバー管理

`/members` でメンバー一覧を確認します。

1. 「新規作成」から氏名、メールアドレス、パスワード、部署、権限、原価率を入力します。時間あたり原価は空欄または0以上の整数円です。
2. メンバー詳細から編集・無効化ができます。

### インポート

`/imports` で、メンバー、案件、アサイン、稼働可能時間、月次予定工数をCSVで一括登録します。

1. インポート種別を選択します。
2. テンプレートをダウンロードして入力します。
3. プレビューで内容を確認します。
4. 「実行」で取り込みます。

マスターCSVエクスポートも可能です。

CSVでも画面入力と同じルールを適用します。`isActive` は `true` / `false`（大文字小文字は不問）または空欄だけを受け付け、アサインは有効なメンバーと未アーカイブ案件、月次予定はさらに有効なアサインを必要とします。案件テンプレートとエクスポートには任意の `effortBudgetHours` 列があり、0.25h単位の0以上の値を指定できます。旧テンプレートのようにこの列がない場合、既存案件の工数予算はクリアされません。

プレビュー後も実行時のトランザクション内で対象状態と月次締めを再確認します。不正行や、プレビュー後に無効化・アーカイブ・アサイン解除・月次保護された行が1件でもあれば、そのファイルからは1件も取り込みません。

### 月次締め

メンバーは `/work-logs/month` で勤務時間と案件別配賦の差分を解消し、月次工数を提出します。対象メンバーは0時間の月も明示提出します。管理者は、当月の活動証跡がある無効メンバーも代理提出できます。提出後の実績変更では、そのメンバー・月だけ下書きに戻ります。予定・稼働可能時間・原価だけの変更では戻りません。

管理者は `/period-locks` の「工数レビューを開始」→「工数を確定」で時間管理を完了できます。必要なのは全対象者の提出と、保存された勤務時間・配賦時間の一致だけです。予定・稼働可能時間・予定確認・単価・契約額・人件費予算は必須ではありません。

金額も管理する場合だけ「任意: 原価の確認・承認」を開きます。工数確定後、欠損単価と必要な契約売上・人件費予算を補い、「原価レビューを開始」→「原価を承認」と進めます。原価側では当月と過去の原価欠損も確認します。日次・月次予定の差は警告であり、工数確定や原価承認を妨げません。「工数確定済み / 原価未確認」は正常な完了状態です。

工数レビュー中・確定済み、または原価工数レビュー中・確定済み、または原価レビュー中・承認済みの月は、管理者を含めて実績、配賦、日次・月次予定、稼働可能時間、コピー・予定反映、CSV、提出、予定確認の変更が保護されます。例外は、選択月と元データの月の原価が両方未確認の場合の、明示単価・理由付きの欠損原価補正だけです。時間・提出・予定確認・工数確定は変更しません。

時間を直す場合は理由を記録して再オープンし、工数・原価を両方未締めに戻します。提出は実績変更まで維持されます。原価承認時だけ案件財務のスナップショットを保存・表示します。再オープン直後は保存値を削除しませんが、未承認の現在値に表示を切り替え、次の原価承認時に保存し直します。

移行では旧原価の未締め・レビュー中・承認済みを、工数の未確定・レビュー中・確定済みに対応付けます。利用可能な操作者・日時を引き継ぎ、システム移行履歴を残します。既存の原価状態・操作履歴・財務スナップショット・提出記録は維持します。旧レビュー中の月は、工数を明示的に確定してから原価承認を続けられます。

工数状態を追加した新しいデータベースに、旧アプリだけを戻してはいけません。旧アプリは工数のみの保護を認識しません。戻す場合はアプリを停止し、移行後の入力を別途保存したうえで、移行前バックアップと対応する旧アプリをセットで復元してください。復元によって戻るデータ期間を利用者に知らせてください。

### 設定

`/settings` で、ワークスペース名とタイムゾーンを編集します。

タイムゾーンには `Asia/Tokyo` や `UTC` など、実行環境が認識できる識別子を指定します。ダッシュボードの「今日」と、工数入力・予定入力・レポートの既定月は、このワークスペースタイムゾーンを基準にします。

### 案件財務レビュー

`/reports/project-financials` で、案件ごとの直接人件費と人件費予算を確認します。管理者だけが利用できます。

1. 案件作成・編集で、税抜の「契約売上」と「人件費予算」を別々に登録します。
2. 対象月と案件を選択します。
3. 選択月の予定人件費・実績人件費、累計実績人件費、人件費予算の残額を確認します。
4. 進行中案件では、人件費予算消化率と目標労務粗利を確認します。
5. アーカイブ済み案件では、確定労務粗利を確認します。

人件費は、月次予定工数と実績工数の保存時点に記録された時間あたり原価から計算されます。原価未設定の予定・実績がある場合は、その時間を0円とは扱わず、金額が不完全であることを表示します。承認済み月は承認時の案件財務スナップショットを表示します。

この画面の労務粗利は、直接人件費だけを対象にしています。仕入れ、外注費、経費、税金、請求・入金、給与計算は含みません。

旧「売上または予算」の値は契約売上・人件費予算へ自動変換されません。案件編集で内容を確認して、改めて新しい項目を入力してください。

## プロフィール

`/profile` で、自身の表示名やパスワードを変更できます。
## 月次の仕事の配分を確認する

管理者は「月次予定工数入力」で対象月を選び、「担当者ごとの月次配分」を確認します。案件ごとの時間、社内作業を含む予定合計、任意の稼働可能時間が並びます。案件内の担当ロールが複数ある場合も、一覧では案件単位に合算します。

予定と稼働可能時間を入力し、担当者ごとの「予定を確認」を押すと「予定上の余力」を表示します。未確認の残り時間は仮の値です。予定がない場合も明示的に確認でき、稼働可能時間が未設定の場合は余力を計算しません。0時間の稼働可能時間は未設定とは区別します。

予定・稼働可能時間の追加、更新、削除、CSV取り込みで、その担当者・月だけ未確認に戻ります。別の管理者が画面表示後に変更していた場合は、最新の内容を見直してから確認してください。工数レビュー中・確定済み、または原価レビュー中・承認済みの月では予定確認も行えません。移行前の保護月は未確認と表示されますが、確認のための再オープンは不要です。

「同じ月の実績と比較」で振り返れます。余力は稼働可能時間から月次予定を引いた月単位の目安であり、実績時間をさらに差し引くものではありません。週ごとの空きや担当できる仕事の種類は別途確認してください。無効メンバーは配分対象外、過去の案件・アサインの予定は履歴として表示します。

予定確認は任意で、メンバーの工数提出・管理者の原価承認とは異なります。未確認でも入力や提出は継続できます。月次予定を配分の基本とし、日次予定は必要な場合だけ利用してください。
