# v0.9.0 — 月次工数提出と締め前確認

月次原価締めの前に、各メンバーがその月の工数入力を完了したことを明示できるようになりました。未提出者を確認してからレビューを開始でき、提出後に実績を修正した場合は対象者だけが自動的に下書きへ戻ります。

## 主な変更

- メンバー自身による月次工数提出と、管理者による代理提出
- 工数が0時間の月も、入力漏れと区別できる明示的な提出
- 未提出メンバーがいる場合のレビュー開始・承認ブロック
- 日次・週次・月次入力、配賦削除、前日コピー、予定から実績への反映後の自動差し戻し
- メンバー向け提出状態と管理者向け提出人数を表示するダッシュボード
- 月次保護と実績更新が競合した場合のトランザクション整合性強化
- 提出状態と対象月をSQLite制約でも検証し、直接DB書き込みによる不正値を防止
- 本番依存の監査警告を解消し、テスト基盤を修正版へ更新

## アップグレード

1. 稼働中のSQLiteファイルを直接コピーせず、READMEの手順でSQLiteデータディレクトリまたはDocker volumeをバックアップしてください。
2. 通常どおり起動すると、migration `0006_abnormal_gauntlet.sql` と `0007_nasty_drax.sql` が順に適用されます。
3. 既存のレビュー中・承認済み月は、対象メンバーをシステム移行済み提出として補完します。未締め月は下書きのままです。
4. 既存の提出データに不正な状態や月がある場合、migrationは途中状態を残さず失敗します。値を確認・修正してから再実行してください。
5. 有効なデータは旧アプリでも扱えるため、アプリケーションだけを戻す場合はSQLite volumeを維持できます。DBスキーマ自体を戻す場合は移行前バックアップから復元してください。

## 対象範囲

月次工数提出は、工数入力の完了を月単位で確認するための機能です。勤怠承認、給与計算、請求・入金、経費、外注費、会計上の締めは対象に含みません。案件財務と月次原価締めは、従来どおり直接人件費のみを対象とします。
