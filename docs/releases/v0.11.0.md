# v0.11.0 — Windowsの簡単導入と、エージェントに任せるインストール

Dockerを使えないWindows PCでも、Node.jsと2つのバッチファイルで導入・起動できるようになりました。エージェントに渡すプロンプトも用意し、ソース取得から起動確認まで同じ手順で進められます。

## 主な変更

- Windows x64向けに `install.bat` と `start.bat` を追加。初回の設定生成、依存関係導入、ビルド、DB準備をまとめ、起動後のヘルス確認からlocalhostのURLを案内します。
- 既存の設定・シークレット・データを保持します。不正設定やポート競合ではエラーで止まり、別のプロセスを終了しません。
- READMEに、公開URLから取得するプロンプトと取得済みフォルダー用のプロンプトを掲載。専用スキルの登録は不要で、Gitがない環境では同じ安定版のZIPを使えます。
- Windows／Dockerの手動導入と、停止・更新・バックアップ・復元ガイドを追加。SQLiteの一貫性バックアップと新しい保存先への復元を補助するコマンドを用意しました。
- 工数実績レポートで終了案件を選べるようになり、案件の終了状態と担当者の無効状態を表示します。適用済み条件、対象月、工数確定状態を確認でき、CSVも同じ条件で出力します。
- 担当者・案件の編集画面に、無効化／アーカイブ後も実績が残ることと、名称・部署・案件種別などの変更が過去レポートへ反映されることを説明。操作権限と案件内の役割を区別し、案件種別の画面表示を日本語で統一しました。

## 初めて導入する場合

- Windows: [導入ガイド](../install/windows.md)に従い、Node.js 22.22以上の22系対応版を用意し、ソースZIPを展開して `install.bat`、次に `start.bat` を実行します。
- Docker: [Docker導入ガイド](../install/docker.md)に従い、固有のシークレットを設定してComposeでソースからビルドします。
- エージェント: [公開URL用／取得済み用のプロンプト](../install/agent.md)をコピーして渡します。管理者情報は利用者が初期設定画面で入力します。

## アップグレード

1. 入力を止め、現在の版の手順で一貫性バックアップを作り、設定ファイルも秘密情報として保管します。稼働中のSQLite本体だけをコピーしないでください。
2. v0.11.0を新しいフォルダーへ取得し、同じシークレットとデータ保存先を引き継ぎます。DockerではComposeプロジェクト名・volume・追加設定も維持します。
3. [運用ガイド](../install/operations.md)に従って準備・起動し、ログインと保存済みデータを確認します。従来の `.env` にサンプル値がある場合は、その値を使えない旨が表示されます。
4. 終了案件を含む過去レポートとCSVを確認してください。既存CSVの列名・順序・コード値は維持します。

v0.10.0から新しいDB移行はありません。新しい導入処理は `.env` を読み、直接起動の既定を `HOST=127.0.0.1`、`PORT=3000` とします。準備・起動・バックアップには同じ設定ファイルを指定してください。通常の `npm start` には導入用の設定読み込みと起動確認が含まれません。

## 対象範囲と制限

- Windows x64、Node.js 22系、Chromium系ブラウザのlocalhost利用を導入検証対象とします。Node.js、npmパッケージ、SQLiteのネイティブ部品を利用できる環境が必要です。
- 起動コンソールを維持して使い、停止はそのコンソールのCtrl+Cで行います。Windowsサービス登録、Node.js同梱ZIP、オフライン配布、Windows ARMは今回の対象に含みません。
- エージェントにはファイル操作・ネットワーク取得・コマンド実行が必要です。組織の制限を変更する指示は含めず、常駐できない環境では最後の起動操作を利用者へ引き継ぎます。
- チーム共有はHTTPS終端を用意してください。署名済みセッションと本番のSecure Cookieは維持します。
- 過去レポートは現在のマスタを参照します。所属・単価・分類の履歴固定、部署／顧客マスタ追加、新しい財務計算は含みません。
- 簡易原価は直接人件費だけです。外注費・経費・間接費・税・請求・入金・給与計算・会計上の締めは対象外です。

## ロールバック

この版に新しいDB移行はありませんが、以前の工数確定の保護を認識しない古い版へアプリだけを戻さないでください。復元はバックアップに対応する版で、新しい保存先へ検査してから切り替えます。導入補助の復元コマンドはmanifestと同じアプリ版を要求します。旧データは確認が終わるまで保持し、復元で失われる入力期間を利用者へ知らせてください。
