## Context

現在のprojectsテーブルには意味が曖昧な`revenueOrBudgetAmount`があり、membersには時間あたり原価、monthly plansとeffort allocationsには原価スナップショットがある。金融情報は管理者だけが入力できるが、現在のダッシュボード、レポート、CSV出力からは意図的に除外されている。

kosuの目的を、小チームが案件売上に対する直接人件費を把握し、残り人件費予算を使って配分を調整し、月次で工数を確定することへ広げる。ただし、会計・請求・給与・経費精算システムにはしない。

## Goals / Non-Goals

**Goals:**

- 管理者が案件ごとに税抜の契約売上と人件費予算を別々に管理できるようにする。
- 保存済みの原価スナップショットから、選択月の予定人件費・実績人件費と、案件累計の実績人件費を集計する。
- 進行中案件では人件費予算の残額・消化率と目標労務粗利を表示する。
- 完了（アーカイブ済み）案件では、契約売上と累計実績人件費から確定労務粗利・確定労務粗利率を表示する。
- 原価スナップショットがない工数をゼロ円として計算せず、金額の不完全性を明示する。
- 金融データと金額を管理者に限定し、メンバー向けペイロードへ含めない。

**Non-Goals:**

- 請求書、入金、売掛金、仕訳、税金、給与、経費精算、外注費、仕入れ、ERP機能を追加しない。
- 進行中案件に対して、全案件原価を保証する最終利益予測を出さない。
- 既存の予定工数対実績工数レポートの意味を金融レポートへ変更しない。
- 旧`revenueOrBudgetAmount`を契約売上または人件費予算へ自動分類しない。

## Decisions

### Decision: 案件の金額基準を契約売上と人件費予算へ分離する

projectsへ`contractRevenueAmount`と`laborCostBudgetAmount`を追加する。両方とも税抜円の任意整数とし、契約売上は売上契約額、人件費予算は直接人件費に使える上限を表す。既存の`revenueOrBudgetAmount`は値の意味が判別できないため残し、新しい2項目は管理者が明示的に入力する。

Rationale:

- 売上と原価予算を同じ金額にすると、残予算と粗利の計算が正しくできない。
- 自動変換は既存案件の値を誤って契約売上または予算として扱う危険がある。

Alternatives considered:

- 既存金額を契約売上へ自動移行: データ損失はないが、旧値が予算だった場合に誤った粗利を出す。
- 月別売上・予算テーブルを最初から導入: 将来は必要になり得るが、現在の案件単位の契約管理には過剰である。

### Decision: 進行中案件は予算消化、完了案件は確定労務粗利を表示する

管理者向け財務レビューでは、次の値を表示する。

- 選択月の予定人件費: 当月monthly plansの`plannedHours * hourlyCostRateSnapshot`。
- 選択月の実績人件費: 当月effort allocationsの`allocatedHours * hourlyCostRateSnapshot`。
- 累計実績人件費: 案件の全期間の実績人件費。
- 残り人件費予算: `laborCostBudgetAmount - 累計実績人件費`。
- 人件費予算消化率: `累計実績人件費 / laborCostBudgetAmount`。
- 目標労務粗利: `contractRevenueAmount - laborCostBudgetAmount`。
- 目標労務粗利率: `目標労務粗利 / contractRevenueAmount`。
- 確定労務粗利: アーカイブ済み案件だけで`contractRevenueAmount - 累計実績人件費`。

進行中案件は残作業の見積もりや外注費がないため、契約売上から現在までの実績人件費を引いた値を利益・着地見込みとして表示しない。

Rationale:

- 進行中案件の見かけ上の利益は、未入力の将来人件費を無視して過大に見える。
- 予算消化と目標粗利は、現在のデータだけで管理者が安全に判断できる。

### Decision: 原価未設定工数を不完全データとして扱う

集計対象の予定または実績に原価スナップショットがない場合、その時間と行数を別途示す。金額合計は「原価未設定を含むため参考値」と明示し、原価未設定分を0円として残予算・粗利を確定値に見せない。

Rationale:

- 古いデータ、原価未設定メンバー、手動移行データを0円にすると、利益と残予算が過大に見える。

### Decision: 専用の管理者向け案件財務レビューを追加する

`/reports/project-financials`に、対象月と案件を確認できる管理者専用のレビュー画面を追加する。案件ごとの累計予算消化と選択月の予定・実績人件費を表示し、予算超過・原価未設定を強調する。既存の`/reports/planned-vs-actual`は工数時間の比較に維持する。

Rationale:

- 工数時間の調整と金額の判断は関連するが、対象者と機密性が異なる。
- 既存レポートのメンバー向け表示を複雑にせず、金融情報の漏えいを防げる。

### Decision: 内部案件は人件費のみを表示する

`internal`または`non_billable`の案件は契約売上・目標労務粗利を必須にせず、設定されていない場合は人件費と人件費予算だけを表示する。

Rationale:

- 内部案件に架空の売上を強制すると、プロジェクト財務の意味が崩れる。

## Risks / Trade-offs

- [人件費だけを粗利として誤解する] → 画面・仕様では労務粗利と明記し、外注費・仕入れ・経費を含まないことを表示する。
- [旧金額の意味が不明] → 自動移行せず、管理者が新しい契約売上または人件費予算を入力するまで旧金額を保持する。
- [原価未設定により金額が不完全] → 不完全な工数を警告し、確定的な残予算・粗利として表示しない。
- [金融情報の漏えい] → ローダー、CSV、画面のすべてで管理者認可を適用し、メンバー向けデータを分離する。
- [税抜・税込の混在] → 初期版は税抜円だけを扱い、税計算をしないことを明記する。

## Migration Plan

1. projectsへ契約売上と人件費予算のnullable列を追加し、旧`revenueOrBudgetAmount`を保持する。
2. 案件作成・編集・CSVインポート/エクスポートへ新しい2項目を追加する。
3. 原価スナップショットを使う管理者専用集計と案件財務レビューを追加する。
4. 既存案件は新しい金額が未設定の状態で動作させ、管理者が確認して入力する。

Rollback strategy:

- 新列はnullableであり、機能を戻しても既存の案件・工数・原価スナップショットは失われない。

## Open Questions

- 将来の仕入れ・外注費は、案件全体の一括原価として持つか、月別原価として持つか。
- 契約変更や売上変更の履歴が必要になった時点で、案件財務の履歴テーブルを追加する。
- 見込み労務粗利は、プロジェクト終了日と残作業見積もりを導入する変更で別途設計する。
